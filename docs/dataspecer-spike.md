# Spike A: Dataspecer

Source read: <https://github.com/dataspecer/dataspecer>, `main` at commit
`6b22dd14ee893ec3503ca6f89aa25d206a33f624` (5 Nov 2026), shallow clone. Code
reading only; nothing was built or run. File references are relative to that
repository. Confidence: **high** = seen directly in code; **medium** = code
seen but behaviour inferred; **low** = not found / unconfirmed.

## 1. Does it generate SHACL from profiles or DSV today?

**Yes, from application profiles (semantic + profile models). High.**

- `packages/shacl-v2/` (`semanticModelsToShacl`, `shaclToRdf`; `src/index.ts`,
  `src/semantic-adapter/shacl-semantic-adapter.ts`). The adapter's tests build
  a profile with `createDefaultProfileModelBuilder` from
  `@dataspecer/profile-model` and generate shapes from it
  (`src/semantic-adapter/shacl-semantic-adapter.spec.ts`, lines ~64–117).
- Wired into artifact generation: `packages/specification/src/specification.ts`
  (~lines 560–572) writes `shacl.ttl` / `shacl-<key>.ttl` per configured file
  via `generateShaclApplicationProfile`, next to the DSV profile
  (`generateDsvApplicationProfile`, ~lines 520–545).
- Configuration: `packages/specification/src/shacl-v2.ts` — policy
  `semic-v1`, options such as `noClassConstraints`,
  `splitPropertyShapesByConstraints`, `controlledVocabularyPattern`,
  `controlledVocabularyScheme`, `profileSpecializationAsSubClassOf`.
- The 2024 "SHACL export is future work" note on the plan page is outdated.
- **Verify:** whether SHACL is generated from an *imported* DSV profile
  (inferred yes, since import produces the same profile entities — medium) and
  how faithful it is for maxCount, `sh:in` and nested shapes (not tested).

## 2. Can it import a DSV file, or a specification through its embedded metadata?

**Via embedded metadata: yes. High. A bare DSV Turtle file: probably not as a profile. Medium.**

- `services/backend/src/routes/import.ts`, `importFromUrl` (~lines 654–690):
  if the URL returns `text/html`, it reads the
  `<script type="application/ld+json">` block (DSV specification metadata),
  converts it to RDF and calls `dsvImport` (~line 486), which uses
  `rdfToDSVMetadata` and follows the listed resources: vocabulary
  (`role.vocabulary`), the DSV application profile
  (`role.constraints` + conformsTo `dsvApplicationProfile` and `profProfile`,
  ~lines 537–546), and structure models. The profile Turtle is parsed with
  `rdfToConceptualModel` (~line 457) from
  `packages/data-specification-vocabulary/src/semantic-model/`.
- Any non-HTML URL goes to `importRdfsModel` (~line 227), i.e. it is treated as
  an RDFS/OWL vocabulary, not as a DSV profile. So a VPE DSV export should be
  published as (or wrapped in) an HTML page with DSV JSON-LD metadata pointing
  at the DSV `.ttl`. **Verify** in WP5b by actually importing.
- Import is URL-based (`POST /resources/import?parentIri=…&url=…`), so the files
  must be reachable over HTTP from the Dataspecer backend. There is also
  `POST /resources/import-zip` for Dataspecer's own package export (not DSV).

## 3. CLI, headless or HTTP route to generate artifacts without the UI?

**HTTP: yes. High. Dedicated CLI: not found. Medium.**

- `services/backend/src/main.ts` (~lines 83–150) exposes REST routes,
  including `POST /resources/import`, `GET /generate?iri=<package>` and
  `GET /experimental/output.zip` (both `getZip` in `routes/generate.ts`,
  returns a ZIP of all artifacts) and `GET /preview/*` (single file).
- Headless use = run the backend (e.g. `docker run -p3000:80 ghcr.io/dataspecer/ws`,
  README), import by URL, then call `/generate`. Not tried; path prefix
  (`apiBasename`) and auth/config **verify**.
- No CLI entry point found in `package.json` files (only `load-lov` and
  `utils/xslt-roudtrip`, unrelated). Low confidence that none exists elsewhere.

## 4. Does it have LLM features?

**No product LLM features found. Medium.**

- Searched `.ts/.tsx/package.json` for openai, anthropic, llm, gpt, gemini,
  ollama: only a code comment "Generated by ChatGPT" in
  `packages/layout/src/graph/graph-metrics/implemented-metrics/edge-crossing-angle.ts`
  and a developer `applications/conceptual-model-editor/CLAUDE.md`. No API
  clients or prompts. Branches, forks and the hosted instance were not checked.

## Consequences for RQ2 (proposal)

- WP2 DSV export from VPE is worth doing: Dataspecer can import it (via HTML +
  JSON-LD wrapper) and regenerate SHACL, which gives an independent compiler to
  compare against VPE's SHACL in WP5b.
- RQ2's LLM contribution does not overlap with Dataspecer features.
